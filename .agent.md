# Agent Context — Recto-versIA

## 1. Identité du projet

| Champ | Valeur |
|-------|--------|
| **Nom** | Recto-versIA — Assistant de correction pédagogique avec IA |
| **Version** | 2.6 (février 2026) |
| **Domaine** | EdTech — outil de correction pour enseignants et élèves |
| **École** | Collège Notre-Dame de Dinant (Belgique) — domaine `@cnddinant.be` |
| **Utilisateur principal** | Jean-Philippe Bolle (professeur) |

**Description** : Application web permettant à un enseignant de corriger des productions d'élèves via des grilles de correction à 6 niveaux, avec assistance IA (précorrection Claude, dictée vocale Whisper). Les élèves rédigent, s'autoévaluent et consultent la correction du professeur.

## 3. Authentification et rôles

| Email | Rôle | Admin |
|-------|------|-------|
| `jeanphilippe.bolle@cnddinant.be` | `prof` | oui |
| Email dans collection `professeurs` | `prof` | non |
| Tout `@cnddinant.be` | `eleve` | non |
| Email dans collection `eleves` (importé dans une classe) | `eleve` | non |
| Autre | non autorisé | — |

- Auth via Firebase (Google OAuth) avec cookie `__session`
- Middleware Next.js : redirige vers `/login` si pas de cookie (sauf `/api/*` et assets statiques)
- Les API Routes vérifient le token Firebase côté serveur via `verifyAuth()` partagé (`src/lib/api-auth.ts`)
- `verifyAuth()` : vérifie le Bearer token, résout le rôle via `resolveUserRole()` (sync hardcodé + fallback async Firestore `professeurs` + fallback `eleves`), retourne `{ uid, email, role, isAdmin }`
- `resolveUserRole()` : 3 niveaux — (1) `getUserRole()` sync (domaine cnddinant.be), (2) collection `professeurs`, (3) collection `eleves` (élèves externes importés dans une classe)
- `isAdmin(email)` : vérifie si l'email est `jeanphilippe.bolle@cnddinant.be` (hardcodé, sync)
- Règles Firestore : `isProf()` étendu avec `exists()` sur la collection `professeurs` ; `isAuthorizedUser()` = domaine autorisé OU professeur enregistré OU document `users/{uid}` existant (créé via `/api/auth/init-user`)
- `AuthContext` : `isAdmin: boolean` dans le state ; fallback API `/api/auth/role` pour les emails non-cnddinant.be (professeurs et élèves externes) ; création document utilisateur via `/api/auth/init-user` (adminDb, bypass rules)

### Année scolaire (calcul automatique)
- Du 25 août de l'année N au 5 juillet de l'année N+1
- Exemple : 25/08/2025 → 05/07/2026 = "2025-2026"

## 4. Modèle de données (Firestore)

### Collection `devoirs`
```typescript
interface Devoir {
  id: string;                    // DEV-YYYYMMDD-XXXX
  classes: string[];             // noms de classes (ex: ["4A", "4B"])
  dateRemise: Timestamp;
  grille: string;                // nom de la grille dans Google Sheets
  intitule: string;
  consignes: string;
  ressources: DevoirRessource | null;
  accesIA: boolean;              // toggle : élève peut utiliser IA (défaut: false)
  disponible: boolean;           // toggle : travail visible par élèves (défaut: false)
  archive: boolean;              // toggle : archivé (défaut: false)
  corrige: boolean;              // toggle : travail classé comme corrigé (défaut: false)
  corrigeDisponible: boolean;    // toggle : corrections/points visibles par élèves (défaut: false)
  createdAt: Timestamp;
  anneeScolaire: string;         // ex: "2025-2026" (calculé auto)
  profId: string;
}

interface DevoirRessource {
  type: 'text';
  content: string;               // rétrocompat (= outils)
  outils?: string;               // HTML riche (liens Ctrl+K) via OutilsEditor Tiptap
  document?: string;             // HTML riche mis en forme via DocumentEditor Tiptap
}
```

### Collection `travaux`
```typescript
interface Travail {
```

### Collection `corrections`
```typescript
interface Correction {
  id: string;                         // CORR-{travailId}
  travailId: string;
  devoirId: string;
  studentId: string;
  profId: string;
  profEmail: string;
  evaluation: Record<string, number>; // {criterionId: level}
  commentaireGeneral: string;
  commentairesCriteres?: Record<string, string>;
  score: number;
  status: 'draft' | 'finalized';
  visibleParEleve: boolean;           // toggle (défaut: false)
  annotatedContent?: string;          // HTML annoté par le prof
  audioAnnotations?: AudioAnnotation[];
  draftAnnotations?: Record<string, DraftItemAnnotation>; // annotations sur le brouillon (clé = itemId)
  createdAt: string;
  updatedAt: string;
  finalizedAt: string | null;
  version: number;
}

interface AudioAnnotation {
  id: string;
  audioData: string;   // base64 data URL (data:audio/webm;base64,…)
  createdAt: string;
}

interface DraftItemAnnotation {
  status?: 'correct' | 'incorrect';  // ✓ ou ✗
  audio?: string;                     // base64 data URL (data:audio/webm;base64,…)

```
> Annotations audio (texte et brouillon) stockées en base64 directement dans Firestore (pas de Firebase Storage). ~30-50 Ko par enregistrement de 10s. Limite 1 Mo/document → ~15-20 annotations par correction.

### Grilles de correction (Google Sheets)
```typescript
interface Grille {
  name: string;
  criteria: GrilleCriterion[];
}
interface GrilleCriterion {
  id: string;
  name: string;
  weight: number;
  levels: GrilleLevel[];
}
interface GrilleLevel {
  level: number;       // 0-5
  description: string;
}
```
- Chaque onglet du classeur Google Sheets = une grille
- API avec cache 5 minutes en mémoire
- **6 niveaux** : Néant (0%), Très insuffisant (15%), Insuffisant (35%), Suffisant (60%), Acquis (80%), Parfaitement acquis (100%)
- Points par critère = (poids × pourcentage_niveau) / 100

## 7. Flux utilisateur

### Professeur
1. Connexion Google OAuth → `/dashboard`
2. Créer un devoir (intitulé, classes, grille, date, consignes, ressources, toggles)
3. Gérer les classes (`/classes`) : CRUD + import Google Classroom
4. Consulter les travaux remis → `/dashboard/travaux/[devoirId]`
5. Ouvrir un travail → voir contenu + auto-évaluation de l'élève
6. Corriger : annoter le texte (orthographe, syntaxe, lexique, audio), évaluer la grille, rédiger commentaires
7. Renvoyer en correction si nécessaire (status `submitted` → `draft`)
8. Toggle "Visible par l'élève" pour rendre la correction accessible

### Élève
1. Connexion Google OAuth → `/activites`
2. Ouvrir un devoir disponible → `/activites/[id]`
3. Rédiger dans l'éditeur Tiptap (polices accessibles, double interligne, indentation)
4. Annoter les ressources (surligner, souligner, raturer, notes marginales, dictionnaire Wiktionnaire)
5. S'autoévaluer sur la grille
6. Remettre le travail (confirmation modale)
7. Consultation en lecture seule après remise
8. Si renvoyé par le prof : ré-éditer et resoumettre
9. Consulter la correction du prof (quand `visibleParEleve === true`)

## 10. Extensions Tiptap personnalisées

Fichier : `src/lib/tiptap-extensions.ts`

- **LineHeight** : interligne personnalisé (`setLineHeight` / `unsetLineHeight`)
- **Indent** : indentation paragraphes (`indent` / `outdent`, Tab/Shift+Tab, 8 niveaux × 30px)

Fichier : `src/lib/tiptap-annotations.ts`

- **SpellingMark** : annotation orthographe (soulignement rouge)
- **SyntaxMark** : annotation syntaxe (soulignement orange)
- **LexiqueMark** : annotation lexique (soulignement noir)
- **ContentLock** : empêche l'édition du contenu texte (autorise les marks). Utilise `instanceof AddMarkStep/RemoveMarkStep` (pas `constructor.name` qui casse en production à cause de la minification)

Cela permet de garder un historique des versions de correction et d'empêcher les modifications accidentelles après envoi à l'élève. ## 20. Règles de travail pour l'agent

### Project Stack
This project uses Next.js with TypeScript and Firebase (Firestore + Auth). Always check Firebase security rules and Firestore document ID patterns (Auth UID vs custom IDs) before writing queries or API routes.

### Code Editing Rules
Before editing UI components, trace the actual component tree to confirm which component is rendered. Do NOT assume a component is used just because it exists — check the parent imports. Run `grep -r 'ComponentName' src/` to verify usage.

### Deployment
When deploying to VPS or running server commands, ALWAYS provide commands for the user to run manually. Never attempt SSH or remote commands directly from the terminal.

### Firebase Constraints
- This project is on Firebase Spark (free) plan. Do NOT suggest Firebase Storage, Cloud Functions, or other paid-tier features. Use Firestore directly for file storage (base64) when needed.
- Before creating Firestore API routes, verify that any required composite indexes exist. List expected indexes in comments and remind the user to create them in the Firebase Console.

### Styling
Always match the existing styling theme (colors, spacing, font choices, component patterns) when building new pages. Check existing pages first with `Read` before creating new UI. The app uses a specific CSS design system — do not introduce conflicting styles.
